# گزارش تست نسخه 2.0.50

## بررسی نسخه ورودی

- آرشیو 2.0.49 سالم و فاقد مسیر خروج از پوشه یا symlink مشکوک بود.
- تست ایستای نسخه ورودی پیش از تغییرات PASS شد.
- تغییرات نسخه‌های 2.0.43 تا 2.0.49 شامل بهبود OTP، تاریخچه پرداخت مشتری، سلسله‌مراتب عملیات و نگه‌داری تماس مجدد در نسخه اصلاح‌شده حفظ شده‌اند.

## تست‌های اجراشده پس از اصلاح

- تطابق نسخه هدر و `SN_VERSION`: PASS (`2.0.50`)
- ساختار PHP و نبود متد تکراری: PASS (تحلیل ایستا)
- بارگذاری و syntax تمام فایل‌های JavaScript: PASS
- توازن ساختاری CSS: PASS
- اتصال hook، shortcode، action و صفحه‌های پنل: PASS
- سیاست زمان انتظار مثبت و deadline محلی: PASS (بررسی invariant)
- مسیر فوری مقدار صفر هنگام ایجاد کارت: PASS (بررسی invariant)
- اجرای فوری مقدار صفر برای ردیف‌های خودکار در انتظار: PASS (بررسی invariant)
- جلوگیری سمت سرور از انتخاب مشتری پس از سررسید: PASS (بررسی invariant)
- حفاظت رکوردهای تاریخی `auto_route_eligible=0`: PASS (بررسی invariant)
- بسته‌بندی استاندارد با یک پوشه ریشه `sales-network-v4`: PASS
- آزمون `unzip -t` روی ZIP نهایی: PASS (بدون خطای داده فشرده)

## محدودیت محیط تست

PHP CLI و نمونه زنده WordPress/MySQL در محیط حاضر در دسترس نبود. بنابراین `php -l` و تست end-to-end واقعی پرداخت/cron باید پیش از انتشار عمومی روی Staging اجرا شود. تست ایستای همراه افزونه این محدودیت را صریح گزارش می‌کند و جای تست Staging را نمی‌گیرد.
