# انتشار 2.0.78 — پایداری خروجی درگاه، کارت مدیر فروش و رفتار مشتری

## اصلاح 502 خروجی زیبال

- پاسخ CSV پیش از فراخوانی API و پردازش داده آغاز می‌شود تا LiteSpeed درخواست را به دلیل سکوت طولانی قطع نکند.
- Report API فقط یک‌بار و با سقف ۱۲ ثانیه فراخوانی می‌شود؛ تکرار قبلی دو درخواست ۴۵ ثانیه‌ای حذف شد.
- خطای زیبال دیگر پاسخ HTTP 502 تولید نمی‌کند. در دسترس نبودن سرویس باعث ادامه خروجی با تراکنش‌های موفق محلی CRM می‌شود.
- کد پیگیری غیرحساس در Header و لاگ مرحله‌ای باقی مانده و Token یا داده مشتری لاگ نمی‌شود.

## شماره کارت بر اساس مدیر فروش

- تنظیم شماره کارت از معاون فروش به مدیر فروش منتقل شد.
- کارت مدیر فروش بالادستی هنگام صدور روی فاکتور Snapshot می‌شود.
- ستون `payment_card_sales_manager_user_id` به‌صورت additive افزوده شد.
- فاکتورهای قبلی Snapshot فعلی خود را حفظ می‌کنند.
- تنظیم‌های قدیمی معاون فروش حذف نمی‌شوند و فقط برای زنجیره‌های کاملاً قدیمی که مدیر فروش ندارند به‌عنوان fallback سازگار خوانده می‌شوند؛ زنجیره دارای مدیر فروش فقط کارت همان مدیر یا کارت پیش‌فرض را می‌گیرد.
- فاکتورهای افزایشی عملیات نیز Snapshot کارت فاکتور مبدأ را حفظ می‌کنند.

## تب رفتار مشتری

- تب رفتار مشتری به پنل تبدیل‌کننده، سرپرست و مدیر فروش اضافه شد.
- جستجو، صفحه‌بندی و نمایش جزئیات Timeline در یک مؤلفه مشترک انجام می‌شود.
- دامنه داده سمت سرور کنترل می‌شود: تبدیل‌کننده فقط پرونده/فاکتور مرتبط، سرپرست فقط زیرمجموعه خود، و مدیر فروش فقط زنجیره فروش خود را می‌بیند.

## کلید فعال‌سازی کارت‌به‌کارت

- تنظیم `sn_card_to_card_enabled` با پیش‌فرض فعال اضافه شد.
- در حالت خاموش، دکمه و فرم کارت‌به‌کارت در فاکتور مخفی، ارسال شماره کارت در پیامک متوقف و ثبت جدید سمت سرور رد می‌شود.
- فیش‌ها و سوابق قبلی برای بررسی مالی حفظ می‌شوند.

## سازگاری

- هیچ Option قدیمی، فاکتور، پرداخت، کیف پول یا سابقه‌ای حذف یا بازنویسی نمی‌شود.
- مهاجرت دیتابیس فقط یک ستون Nullable اضافه می‌کند.
- مسیر پرداخت آنلاین، Callback، تأیید/رد مالی و پورسانت تغییری نکرده است.
