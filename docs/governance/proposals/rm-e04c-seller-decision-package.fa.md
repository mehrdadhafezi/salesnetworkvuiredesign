## ۵. R5-SEC-01 — هویت فرد و تفکیک وظایف

| مورد | شرح |
|---|---|
| مسئله | آیا «فرد» احرازشده با پیوند حساب-به-فرد لازم است تا SoD برای هر انسان اعمال شود؟ |
| پیاده‌سازی فعلی | هر حساب یک کاربر قدیمی است؛ نابرابری حساب، دو انسان را ثابت نمی‌کند. خواندن‌های «مال خود» در سطح حساب‌اند و برای خواندن کافی‌اند. |
| گزینه‌های ثبت‌شده | A ثبت فرد توسط منابع انسانی با پیوند بازبینی‌شده و برگشت‌پذیر · B سامانهٔ هویت بیرونی · C SoD اعلامی بدون موجودیت فرد · D مسدود ماندن |
| پیامد امنیتی | C استقلال انسان را ثابت نمی‌کند (R5). D همهٔ تصمیم‌های وابسته به SoD را مسدود نگه می‌دارد. |
| پیامد کسب‌وکار | خواندن فروشنده به این تصمیم وابسته نیست؛ اعطای grant با تأیید فرد دیگر و هر اقدام مالی حساس وابسته است. |
| پیامد مهندسی | A: موجودیت فرد + رکورد پیوند + ارزیابی SoD؛ B: زیرساخت جدید. |
| توصیه | **گزینهٔ A**؛ B فقط اگر سازمان سامانهٔ هویت دارد. (R5: «A یا B نیاز SoD را برآورده می‌کنند؛ C نه».) |
| چرا | با دادهٔ موجود منابع انسانی سازگار است و ریسک ادغام نادرست با بازبینی دونفره کنترل می‌شود. |
| شواهد ناقص | منبع هویت کارکنان در منابع انسانی؛ روش راستی‌آزمایی؛ بازبینی حریم خصوصی. |
| تأییدکنندگان | امنیت، منابع انسانی، حقوقی (حریم خصوصی)، محصول (R5). |
| آنچه مسدود می‌ماند | C3؛ «درخواست‌کننده ≠ تأییدکننده» در C1 در سطح فرد؛ هر اقدام حساس SoD. **پرسش باز:** آیا ترکیب نقش فروشنده با نقش بازبین مالی برای یک فرد ممنوع است؟ (این سند پاسخ نمی‌دهد.) |
