# 2.0.118 — مجوز صدور دستی و ارسال مجدد پیامک

- فروشنده با تنظیم پیش‌فرض، مجوز صدور دستی را از نزدیک‌ترین سرپرست در سلسله‌مراتب HR می‌گیرد. تنظیم صریح خود فروشنده اولویت دارد. ارتباط قدیمی sn_supervisor_id فقط در نبود زنجیره HR استفاده می‌شود.
- تب صدور دستی و ثبت بدون lead_id فقط با مجوز صریح «مجاز» برای خود فرد یا مجوز ارث‌برده باز می‌شوند. بررسی مالکیت شماره‌ها، محدوده فروشنده، محصول و مبلغ پابرجاست.
- پیامک الگوی فاکتور فراز یک درخواست با سقف انتظار ۱۰ ثانیه دارد؛ تکرار خودکار همان درخواست با انتظار ۳۰ ثانیه حذف شد.
- ارسال ساده ملی‌پیامک با نام کاربری و رمز تنظیم‌شده، به API key جداگانه نیاز ندارد.
- خطای پیامک پس از COMMIT، ثبت موفق فاکتور را به خطای ثبت تبدیل نمی‌کند.
- ارسال مجدد پیامک خطای نشست، پاسخ غیر JSON و خطای سرویس را قابل فهم نمایش می‌دهد. خطای ثبت لاگ پس از ارسال، نتیجه موفق پیامک را معکوس نمی‌کند.

## بررسی‌ها

- آزمون ایستای افزونه و بررسی syntax جاوااسکریپت اجرا شدند.
- چهار آزمون رفتاری رابط ارسال مجدد: موفقیت، خطای سرویس، پاسخ HTML با HTTP 502 و نشست منقضی؛ یک درخواست و آزادشدن دکمه در همه حالت‌ها بررسی شد.
- PHP CLI، وردپرس، دیتابیس و حساب پیامک تولید در محیط توسعه موجود نیستند. ارسال واقعی و صحت اجرا در سایت باید بررسی شوند.
- علت خطاهای سرور در سایر صفحات بدون محل وقوع و لاگ سایت مشخص نیست.

## بررسی پس از نصب

1. در HR مجوز سرپرست را «مجاز» و تنظیم فروشنده را پیش‌فرض بگذارید؛ پس از تازه‌سازی پنل فروشنده، تب صدور دستی باید باز باشد.
2. با تنظیم فروشنده روی «غیرمجاز»، صدور باید بسته شود.
3. ارسال مجدد یک فاکتور متعلق به همان کاربر را بررسی کنید. در خطای ارتباط، پیش از تکرار دستی وضعیت ارسال در پنل پیامک را ببینید.
