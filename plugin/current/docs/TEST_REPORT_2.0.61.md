# گزارش تست نسخه 2.0.61

- نسخه هدر افزونه و `SN_VERSION`: PASS — `2.0.61`
- تحلیل ایستای کامل پروژه: PASS
- تست رگرسیون نصب تازه نقش‌های فروش عملیات: PASS
- وجود سمت‌های مدیر/سرپرست/کارشناس فروش عملیات در seed اصلی HR: PASS
- وجود نگاشت نقش‌های وردپرس به سمت‌های HR: PASS
- وجود مسیر self-heal برای نصب ناقص: PASS
- وجود سه سمت در lookup داخلی پنل HR: PASS
- تشخیص برچسب فارسی نقش‌های عملیات: PASS
- زنجیره مجاز مدیر ← سرپرست ← کارشناس: PASS
- بررسی نحو JavaScript ابزار تست، فلو عملیات و پروفایل مشتری: PASS
- بررسی فایل‌های ارجاع‌شده، متدهای تکراری، callbackها، routeها و shortcodeها: PASS

## ایمنی داده

- عملیات مخرب دیتابیس اضافه نشده است.
- پروفایل، assignment، مالکیت کارت و تاریخچه موجود بازنویسی نمی‌شود.
- self-heal فقط role، position و role-position mapping سیستمی را ترمیم می‌کند.

## محدودیت محیط تست

در محیط ساخت، PHP CLI و WordPress/MySQL اجرایی در دسترس نبود؛ بنابراین `php -l` و تست مرورگری واقعی باید روی Staging اجرا شوند.

## تست پیشنهادی Staging

1. افزونه را روی دیتابیس خالی فعال کنید.
2. در HR بخش افزودن دستی نیرو، وجود هر سه سمت فروش عملیات را بررسی کنید.
3. ابتدا مدیر، سپس سرپرست با بالادستی مدیر، سپس کارشناس با بالادستی سرپرست بسازید.
4. با هر سه حساب وارد شوید و route پنل مربوطه را بررسی کنید.
5. یک نصب 2.0.60 ناقص را به 2.0.61 ارتقا دهید و بررسی کنید گزینه‌ها بدون تغییر در پروفایل‌ها و تخصیص‌های قبلی ظاهر شوند.
