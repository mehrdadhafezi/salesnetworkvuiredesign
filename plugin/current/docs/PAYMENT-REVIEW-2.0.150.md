# بررسی پرداخت و اصلاح ساعت خروجی — 2.0.150

## اصلاحات انجام‌شده

- خروجی تاریخ پرداخت به تاریخ جلالی و ساعت تهران تبدیل می‌شود؛ ثانیه‌ها و جابه‌جایی روز در نیمه‌شب حفظ می‌شوند.
- زمان‌های دارای Z یا اختلاف ساعت صریح، دوباره جابه‌جا نمی‌شوند. زمان رکوردهای داخلی مطابق منطقه زمانی وردپرس تفسیر می‌شود.
- برای زمان بدون منطقه زمانیِ گزارش زیبال، مبنای UTC در نظر گرفته شده است. این مبنا با فیلتر `sn_zibal_report_naive_timezone` قابل تغییر است؛ نمونه واقعی پاسخ زیبال در محیط ساخت موجود نبود. برای زمان‌های جلالیِ فاقد اختلاف ساعت نیز همین مبنا اعمال می‌شود.
- خطای به‌روزرسانی ردیف تراکنش‌ها یا ثبت نهایی دیتابیس در تأیید مالی، باعث بازگشت عملیات و نمایش خطا می‌شود.

## وضعیت محدودیت ۱۰۰ ردیف

این مورد هنوز رفع نشده است. مسیر گزارش زیبال فقط یک درخواست می‌فرستد. برای پیاده‌سازی قابل اتکای دریافت ادامه گزارش، پارامترهای مستند درخواست و ساختار پاسخ Report API لازم است. صفحه رسمی https://help.zibal.ir/platform/ هنگام بررسی در دسترس نبود و خطای timeout/504 داد؛ نام و مبنای پارامتر صفحه‌بندی حدس زده نشده است.

گزینه خروجی داخلی CRM در نسخه قبلی محدودیت ۱۰۰ ردیف در کوئری ندارد، اما جایگزین گزارش کامل زیبال نیست؛ رکوردهایی که فقط در زیبال وجود دارند در آن قابل بازیابی نیستند.

## بررسی‌های اجراشده

- بررسی نحوی ۲۷ فایل PHP با PHP 8.5 در WebAssembly: موفق.
- ۳۲ بررسی اجرایی PHP برای ساعت، جمع تراکنش‌ها و اعتبارسنجی مبلغ: موفق.
- ۱۰ بررسی اجرای متد واقعی ثبت با مدل آزمایشی دیتابیس: ثبت اطلاعات واریز سپس فیش، حفظ مبلغ و مشخصات، تکرار درخواست، رد مبلغ اضافه و بازگشت عملیات هنگام خطای درج: موفق.
- ۶ بررسی JavaScript برای فیش چندتایی و ۷ بررسی تراکنش‌های مستقل: موفق.
- ابزار بررسی ایستا همان پنج ایراد/عدم انطباق قبلی را گزارش می‌دهد؛ خطای جدیدی گزارش نشد.

این بررسی‌ها آزمون نصب روی وردپرس، تراکنش واقعی MySQL یا اتصال زنده به درگاه نیستند و نبود همه باگ‌های افزونه را تضمین نمی‌کنند.
