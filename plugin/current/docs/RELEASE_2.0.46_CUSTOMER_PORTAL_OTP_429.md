# انتشار 2.0.46 — اصلاح محدودیت 429 ورود مشتری

## تشخیص

در گزارش مرورگر نسخه 2.0.45 فعال بود و خطای قبلی 502 دیگر دیده نمی‌شد. درخواست در مرحله `requestCode` با HTTP 429 متوقف می‌شد. علت، باقی‌ماندن cooldown/شمارنده تست‌های قبلی و ناتوانی رابط در ادامه با OTP فعال قبلی بود.

## اصلاح

- اگر برای همان مشتری یک OTP منقضی‌نشده وجود داشته باشد، همان challenge برگردانده می‌شود و پیامک تکراری ارسال نمی‌شود.
- درخواست تکراری معتبر دیگر به خطای 429 تبدیل نمی‌شود و فرم مستقیماً مرحله ورود کد را نمایش می‌دهد.
- JavaScript هنگام در جریان بودن درخواست، submit تکراری را نادیده می‌گیرد.
- namespace محدودکننده به `v2` تغییر کرد تا شمارنده‌های باقی‌مانده نسخه قبل مشتری را پس از ارتقا قفل نکنند.
- محدودیت واقعی ارسال پیامک، انقضای پنج‌دقیقه‌ای، هش کد و سقف پنج تلاش تأیید همچنان فعال هستند.

## پذیرش

1. نسخه 2.0.46 را نصب و تمام کش‌ها را پاک کنید.
2. یک‌بار کد بگیرید و بلافاصله دوباره روی ارسال کلیک کنید؛ باید پیام استفاده از کد قبلی دیده شود و 429 رخ ندهد.
3. همان کد را وارد کنید و ورود موفق به پروفایل را بررسی کنید.
4. کد اشتباه و منقضی را نیز تست کنید.
