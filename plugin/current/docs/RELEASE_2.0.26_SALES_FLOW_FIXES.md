# Sales Network 2.0.26 — اصلاح چرخه فروش و پیگیری تبدیل

## دامنه انتشار

- مبلغ دلخواه پرداخت مرحله‌ای از بیشتر از صفر تا حداکثر مبلغ کل/مانده پذیرفته می‌شود.
- مبلغی که دقیقاً برابر کل یا مانده است به مرحله کامل/تسویه مانده تبدیل می‌شود.
- رویداد ادامه فلو (`sn_invoice_paid`) فقط پس از صفرشدن مانده فاکتور اجرا می‌شود؛ پرداخت ناقص صرفاً صف تکمیل واریزی را ایجاد می‌کند.
- پنل مشترک تبدیل برای فروشنده، تبدیل‌کننده و سرپرست وضعیت‌های جواب نداده، تماس مجدد، انصراف با علت اجباری و ارسال لینک پرداخت را پوشش می‌دهد.
- تماس مجدد تاریخ و ساعت آینده می‌گیرد، در پنل سررسید را برجسته می‌کند و یک یادآور پیامکی برای مسئول فعلی پرونده زمان‌بندی می‌کند.
- صدور فاکتور جدید از «آماده‌های اقدام» سرپرست از یک مجوز داخلی و محدود به همان پرونده استفاده می‌کند؛ مجوز صدور دستی عمومی تغییر نکرده است.
- نتیجه صدور فاکتور برای خود سرپرست نمایش داده می‌شود و قفل کوتاه‌مدت از صدور تکراری با دوبار کلیک جلوگیری می‌کند.
- بایگانی مدیر فروش همچنان افزایشی است و داده عملیاتی را حذف نمی‌کند. شمارنده و فهرست فقط موارد حل‌نشده را نشان می‌دهند و پرداخت دیرهنگام بایگانی را حل می‌کند.

## مهاجرت داده

مهاجرت فقط ستون‌های nullable/default-safe زیر و indexهای مرتبط را اضافه می‌کند:

- `converter_followup_at`
- `converter_followup_reminded_at`
- `converter_followup_reminder_attempts`
- `converter_followup_reminder_error`
- `referral_item_id` در جدول فاکتورها، برای بازیابی امن صدور تکرارشده از صف اقدام

هیچ جدول یا رکوردی حذف، rename یا بازنویسی گروهی نمی‌شود. ردیف‌های قدیمی بدون مسیر تبدیل نیز مثل قبل به مسیر صف سرپرست می‌روند.

## کنترل قبل از انتشار

1. از دیتابیس و پوشه افزونه نسخه پشتیبان بگیرید و ابتدا روی Staging نصب کنید.
2. `php -l` را روی تمام فایل‌های PHP اجرا کنید؛ محیط ساخت این نسخه PHP CLI نداشت.
3. فروشنده یک فاکتور مرحله‌ای با مبلغ کمتر از کل و یک فاکتور با مبلغ دقیقاً برابر کل ثبت کند.
4. پس از تأیید مرحله ناقص، نبودن ادامه فلو و وجود صف تکمیل واریزی را بررسی کنید؛ سپس با پرداخت مانده، ادامه فلو را بررسی کنید.
5. سرپرست در «آماده‌های اقدام» یک فاکتور جدید صادر کند و نمایش پیام موفق/خطا و عدم صدور تکراری را بررسی کند.
6. برای هر سه نقش فروشنده خودتبدیل، تبدیل‌کننده و سرپرست خودتبدیل، تماس مجدد آینده ثبت و سررسید/پیامک یادآور را بررسی کنید.
7. هر پنج زیرتب بایگانی مدیر فروش و حل‌شدن خودکار یک مورد پس از تأیید پرداخت دیرهنگام را بررسی کنید.

## آزمون بسته

`node tools/static-audit.js` باید PASS شود. این آزمون wiring، syntax فایل‌های JavaScript، توازن CSS، عدم وجود متد تکراری، قرارداد پرداخت مرحله‌ای، صدور کنترل‌شده سرپرست، یادآور تماس و بایگانی مدیر فروش را بررسی می‌کند.
