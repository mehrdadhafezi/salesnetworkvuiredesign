# Release 2.0.86 — Card payment access hotfix

## مشکل

در نسخه 2.0.85، عملیات داخلی ثبت اطلاعات کارت‌به‌کارت از پنل فروش/سرپرست/تبدیل‌کننده در صورت رد شدن بررسی محدوده داخلی، به‌اشتباه وارد مسیر اعتبارسنجی لینک عمومی می‌شد. چون درخواست پنل داخلی به‌طور صحیح `access_token` عمومی ارسال نمی‌کند، پیام «لینک فاکتور معتبر نیست یا منقضی شده است» نمایش داده می‌شد.

همچنین نمایش فاکتورهای مدیریتی با `SN_Scope_Service` انجام می‌شد اما write access پرداخت از resolver قدیمی‌تری استفاده می‌کرد؛ این دو مسیر در بعضی ساختارهای HR می‌توانستند نتیجه متفاوت بدهند.

## اصلاح

- بررسی نقش/سمت پرداخت داخلی با resolver اصلی HR همسان شد.
- برای سرپرست، سرپرست ارشد و مدیر فروش، دسترسی ثبت پرداخت با همان `SN_Scope_Service::can_view_invoice()` که محدوده فاکتور را تعیین می‌کند کنترل می‌شود.
- اگر درخواست داخلی بدون توکن عمومی واقعاً مجاز نباشد، دیگر به مسیر public-token سقوط نمی‌کند و پیام دسترسی داخلی صحیح برمی‌گردد.
- اگر کاربر لاگین باشد ولی یک لینک عمومی واقعی با `access_token` باز کرده باشد، fallback عمومی همچنان حفظ شده است.
- مسیر آپلود فیش سرپرست نیز با همان Scope Service همسان شد.
- هیچ مجوز جدیدی برای فروشنده ایجاد نشده است: فروشنده همچنان فقط اطلاعات واریز فاکتور مجاز خودش را ثبت می‌کند و آپلود فیش برای او مسدود است.

## داده و مهاجرت

- بدون migration دیتابیس.
- بدون حذف/تغییر رکوردهای فاکتور، پرداخت، فیش یا HR.
- تغییر فقط در authorization routing و تشخیص مسیر public/internal است.
