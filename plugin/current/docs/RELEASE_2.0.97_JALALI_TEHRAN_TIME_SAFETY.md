# نسخه 2.0.97 — ایمنی تاریخ جلالی و ساعت تهران

## هدف

یکسان‌سازی ورودی، نمایش، مقایسه و زمان‌بندی تاریخ‌ها در CRM با تقویم جلالی و منطقه زمانی `Asia/Tehran`، بدون بازنویسی یا مهاجرت داده‌های تاریخی.

## تغییرات اصلی

- اضافه شدن لایه مرکزی زمان تهران برای «اکنون»، نام فایل خروجی، تبدیل timestamp و خواندن/نوشتن تاریخ MySQL.
- اعتبارسنجی مرکزی تاریخ جلالی با کنترل روزهای ماه و اسفند سال کبیسه.
- تبدیل ورودی «تاریخ جلالی + ساعت تهران» به timezone ذخیره‌سازی فعلی وردپرس برای حفظ سازگاری عقب‌رو.
- اصلاح زمان‌بندی تماس مجدد در فلو اعتبارسنجی، عملیات و پنل فروشنده.
- حذف آخرین ورودی مرورگرمحور `datetime-local` و جایگزینی با تاریخ جلالی و ساعت تهران.
- اصلاح محاسبات آرشیو خودکار فروشنده که به timezone سیستم‌عامل وابسته بود.
- اصلاح نمایش زمان جزئیات مالی و زمان تست پیامک اعتبارسنجی.
- اصلاح ثبت زمان واریز دستی برای تفسیر صریح ساعت تهران.
- یکسان‌سازی تاریخ/ساعت نام فایل‌های CSV بر اساس تهران.
- حذف تبدیل‌های شکننده JavaScript مبتنی بر `toLocaleString` و استفاده از `Intl.DateTimeFormat(...).formatToParts`.

## سازگاری داده

- هیچ جدول یا ستون جدیدی اضافه نشده است.
- هیچ رکورد تاریخی بازنویسی نمی‌شود.
- مقادیر MySQL قبلی همچنان با timezone تنظیم‌شده وردپرس خوانده می‌شوند.
- فقط در مرز ورودی و نمایش، تبدیل صریح تهران انجام می‌شود.

## کنترل‌های رگرسیون

- نبود `date`، `gmdate`، `strtotime` و `wp_date` در منطق اجرایی افزونه.
- نبود `datetime-local` در فرم‌ها.
- نبود تبدیل تاریخ JavaScript با بازتفسیر رشته محلی مرورگر.
- کنترل اتصال فلو اعتبارسنجی و عملیات به اعتبارسنج مشترک تهران.
- اجرای syntax check برای همه فایل‌های JavaScript و audit جامع افزونه.

## تست محیط واقعی

به علت نبود PHP CLI و WordPress/MySQL در محیط ساخت، اجرای `php -l` و تست نهایی روی Staging همچنان الزامی است. سناریوهای پیشنهادی: تماس مجدد اعتبارسنجی، تماس مجدد عملیات، ثبت واریز دستی، آرشیو جواب‌نداده و نمایش جزئیات مالی.
