# انتشار 2.0.62 — کنترل SMS پروفایل، مسیر محصول* و خروجی دستی API

این نسخه Patch مستقیم روی 2.0.61 است و فلوهای موجود را بازسازی نمی‌کند.

## تغییرات

1. تنظیم جدید `sn_customer_portal_invite_sms_enabled` در تنظیمات پیامک:
   - روشن: پیامک دعوت/لینک ورود پروفایل پس از فعال شدن کارت ارسال می‌شود.
   - خاموش: پیامک دعوت ارسال و Retry نمی‌شود؛ OTP امنیتی ورود دست‌نخورده می‌ماند.

2. تنظیم جدید محصول* `_sn_operations_self_activation_allowed`:
   - پیش‌فرض برای محصولات قدیمی: فعال، برای سازگاری با رفتار قبلی.
   - غیرفعال: کارت جدید مستقیماً وارد فلو فروش عملیات می‌شود.
   - اگر مسیر HR فقط یک کارشناس فروش عملیات مشخص داشته باشد، تخصیص مستقیم انجام می‌شود؛ در مسیرهای چندکارشناسه کارت به صف سرپرست/مدیر می‌رود تا تخصیص تصادفی نشود.
   - مقدار تنظیم هنگام ایجاد کارت در `sn_project_operations.customer_self_activation_allowed` Snapshot می‌شود.

3. خروجی دستی مرحله API کیف پول:
   - دکمه «خروجی CSV برای ثبت دستی در سیستم مقصد» در پنل کارشناس اجرایی عملیات.
   - خروجی شامل همان اطلاعات اصلی Payload شارژ API است و قرارداد API اصلی تغییر نکرده است.
   - دانلود خروجی فقط برای کارشناس تخصیص‌یافته/مدیر سایت و با Nonce معتبر ممکن است.

4. اعتبار صفر برای محصول*:
   - ذخیره مقدار 0 مجاز است.
   - اعتبار صفر در پروفایل مشتری و بخش‌های مرتبط به شکل «اعتبار 0» نمایش داده نمی‌شود.
   - فعال‌سازی عادی برای کارت با اعتبار پایه صفر مجاز نیست؛ مسیر افزایشی باقی می‌ماند.

5. HR:
   - `operations_executive_manager` به انتخاب‌گر مدیر بالادستی اضافه شد.
   - Bulk hierarchy نیز رابطه `operations_execution_expert -> operations_executive_manager` را معتبر می‌داند.

## Migration

`SN_Operations_Flow::DB_VERSION` به `2026-09-16-product-routing-credit-zero-v6` ارتقا یافته و `dbDelta` ستون زیر را اضافه می‌کند:

`customer_self_activation_allowed TINYINT(1) NOT NULL DEFAULT 1`

در نتیجه رکوردهای قدیمی رفتار سابق را حفظ می‌کنند.
