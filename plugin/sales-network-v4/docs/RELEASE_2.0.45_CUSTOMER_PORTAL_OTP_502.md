# انتشار 2.0.45 — رفع خطای 502 ورود پروفایل مشتری

## علت فنی

درخواست‌های ارسال و تأیید OTP پروفایل مشتری به‌عنوان AJAX داخلی افزونه، کل هسته مدیریتی CRM و تمام ثبت‌کننده‌های اکشن آن را بارگذاری می‌کردند. در زمان تأیید کد نیز یک هوک توسعه‌پذیر پیش از ارسال پاسخ JSON اجرا می‌شد. روی میزبان‌هایی با محدودیت worker یا افزونه‌های امنیتی/ورود، این مسیر می‌توانست پیش از رسیدن پاسخ به مرورگر با timeout و HTTP 502 متوقف شود.

## اصلاح

- اکشن‌های `sn_customer_portal_send_otp` و `sn_customer_portal_verify_otp` در bootstrap سبک اجرا می‌شوند.
- مسیر OTP فقط کلاس‌های لازم برای شناسایی مشتری، هش کد، پیامک و نشست وردپرس را بارگذاری می‌کند.
- هیچ هوک ورود توسعه‌پذیری داخل پاسخ AJAX تأیید کد اجرا نمی‌شود.
- پاک‌کردن عمومی کوکی‌ها برای درخواست ناشناس حذف شد؛ فقط اگر کاربر دیگری از قبل وارد باشد نشست قبلی پاک می‌شود.
- ایجاد کاربر جاری، کوکی ورود و ثبت زمان ورود تحت کنترل خطا قرار گرفت.
- OTP فقط پس از ساخته‌شدن موفق نشست مصرف می‌شود؛ شکست موقت ساخت نشست کد معتبر را بی‌دلیل از بین نمی‌برد.
- nonce، انقضا، تطبیق شماره، هش OTP، سقف تلاش و کنترل عضویت فعال بدون تغییر باقی مانده‌اند.

## تست پذیرش Staging

1. کش صفحه، کش افزونه و CDN را پاک کنید.
2. `/biawin/` را در مرورگر ناشناس باز کنید.
3. شماره مشتری دارای عضویت فعال را وارد و کد را دریافت کنید.
4. کد صحیح را ثبت کنید؛ پاسخ AJAX باید JSON موفق باشد و صفحه پروفایل باز شود.
5. کد اشتباه، منقضی و کد قبلی پس از ارسال مجدد را تست کنید.
6. در Network مرورگر کنترل کنید هر دو درخواست OTP به `admin-ajax.php` پاسخ JSON بدهند.
7. در صورت باقی‌ماندن 502، لاگ upstream/PHP-FPM همان ثانیه را بررسی کنید؛ خطای جدید ساخت نشست با پیشوند `SN customer portal OTP login failed` ثبت می‌شود.
